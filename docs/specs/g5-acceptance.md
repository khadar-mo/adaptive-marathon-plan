# Contextual fitness profile

Issue #31 implements Part A §§6.3, 8, 10–12 and T13 of the Marathon Coach developer master specification v1.0. The profile has two input clocks. **T** is the event cutoff for completed sessions, measured intervals and reported context. **K** is the knowledge cutoff for source versions, classifications, QC decisions and corrections. Capture creation is a third, server-recorded clock.

## Calculation and input contract

Open **Fitness profile** from History. The initial version uses the selected G2 intervals, G4 primary 112-day configuration, G3 exposure and source-compatible wellness streams. An ordinary run can update exposure without changing a best effort. To compare a set of runs, enter their route, conditions, grade and any reported HR or scale-qualified RPE under **Edit comparison evidence**. Choose **Define a descriptor version** to specify independent duration, grade, effort and pace bounds. Apply the new version to the same history to inspect the included runs and each exclusion.

| Operation | Public interface |
| --- | --- |
| Read current or historical state | `GET /api/fitness` takes `as_of`, `knowledge_cutoff`, `mode` and `config_version`. |
| Select time policy | `EVENT_TIME_RECONSTRUCTION` uses current knowledge unless K is supplied. `AS_KNOWN` defaults K to T and requires K ≤ T. Both enforce version availability. |
| Save, list and inspect | `POST /api/fitness/capture` accepts the same four fields as JSON. `GET /api/fitness/snapshots` lists captures. Read `/api/fitness/snapshots/{id}` or `/fitness/snapshots/{id}` for the original result and explained changes from the preceding saved state. A repeated capture with the same input bundle returns the original ID. |
| Audit/rebuild | `GET /api/fitness/snapshots/{id}/inputs` returns the frozen bundle. `/replay` checks code identities, rehashes frozen inputs, recomputes contextual outputs and compares the result. G2/G4 evidence is the captured upstream calculation. G6 owns independent forecast backtesting and full source replay. |
| Define a policy | `POST /api/fitness/configurations` accepts a new `version`, `actor`, `reason` and `config`. Changing a used name returns 409. Select an existing G4 estimator configuration with `estimator_config`. |
| Record or correct field evidence | `POST /api/fitness/run-context` accepts an exact active completed run's `activity_id` and `canonical_version_id`, supporting source/reference, actor/reason and observed fields. Corrections name the current `previous_id`. Original bytes, revision and server receipt survive corrections. A later canonical change leaves earlier references visible for reconfirmation. |
| Use in a downstream transaction | `fitness.collect(db, archive, T, K, mode, config_version=...)` freezes version-bounded inputs on the caller's active SQLite transaction. `fitness.calculate(bundle)` consumes those inputs. `fitness.assemble(...)` provides the combined read. These entry points accept normalized UTC clocks. |

The run comparison uses inclusive bounds and exact supplied route and conditions. Session duration and pace use completed elapsed seconds and distance. A reported mean HR can be supplied, or the profile uses the arithmetic mean of the recorded heart-rate samples with its method shown. A supplied session RPE or unambiguous linked post-run RPE retains its scale definition. Two matched sessions provide one anecdotal comparison. Three or more show consecutive observed pace changes and the median pace. Coverage and environmental selection remain visible.

The sustained descriptor applies its pace band to consecutive, positive-distance original sample edges within a canonical running block. The late-block threshold is a recorded cumulative distance. Both require QC-eligible continuous spans with the original source checksum, sample indices, times and exact rational coordinates. A rejected full span can leave a shorter eligible span. Late blocks include HR sample count, endpoint elevation and separately identified session RPE. Thresholds are supplied per version. Longest sessions and time on feet preserve G3's separate authoritative value, known subtotal, completeness and elapsed/timer bases.

Wellness groups keep unit, source, method, calibration, origin, interpretation, local timezone, value type and daily input policy. The reference uses valid daily values on local dates T−28 through T−1. At least 14 observed days support a baseline by default. Same-day ambiguity follows the recorded input policy. Date-only data preserve their unknown measurement instant. Current-day missingness, present count, coverage reports and missing reasons remain independent of baseline availability. Optional robust deviation requires an explicit stream, positive epsilon in the metric's units and direction. Its denominator is the larger of 1.4826 × median absolute deviation and epsilon. The raw signed result retains that direction metadata.

## Acceptance record

1. **Requirements.** The seven returned dimensions are all-time observations, recent observations, candidate critical speed, endurance, exposure, recovery and quality. Part A §11 quality dimensions remain separate. The default personal predictive status is `UNTESTED`. A method can enter `FAILED_VALIDATION` only through subsequent evaluation evidence. No personal outcome dataset or interval calibration ships with this gate.
2. **Scope.** The profile consumes merged G1–G4 and workout/context evidence. It adds descriptor definitions, exact run annotations and fitness snapshots. Fueling practice and weekly availability retain their independent input streams and planner ownership.
3. **Changes.** The local navigation opens a profile with observed times, provisional fits, exposure, wellness baseline/freshness, missingness, trace source links and strengths/feedback. A captured profile records field-by-field changes, reason, prior and current values.
4. **Fixtures.** Physical FIT uploads include a 5,000 m session with a 1,500.375 s summary and 1,500 s observed interval, three ordinary runs at 300/330/360 s per km, a paused trace and a future session. A synthetic SQLite database exported by the original G0 build exercises the pre-canonical read path.
5. **Tests.** `tests/test_fitness.py` covers T13, source/knowledge clocks, 13/14 days, current-day and day-29 exclusion, precise delta and zero-MAD epsilon, source/calibration separation, two RPE scales, observed trend and exclusions, S&C, later QC decisions, old-format missing processing, exact decimal input, conflicts, idempotence and replay. An explicit one-workout overlap policy produces `CONFLICTED_EVIDENCE` while the supported observation remains inspectable. The combined fitness, context, fueling and availability checks passed 136 tests, including the real fitness browser flow.
6. **API inspection.** The earliest runnable commit was checked through the normal app against independently expected rolling windows, baseline boundaries and existing-format data. The coordinator subsequently checked the three-run median, late ordinary import, explicit QC rejection and immutable earlier snapshots. The regression initially failed for a QC annotation made after T. Applying decisions at their K while keeping the measured effort at T fixed both PB and endurance selection.
7. **UI inspection.** `tests/test_fitness_browser.py` starts Uvicorn and Chromium, uploads a FIT, enters run evidence, defines matching and segment rules, sees a real positive match, saves a snapshot and checks the replay result. It exercises keyboard navigation and the 375-pixel layout and checks the browser console.
8. **Lineage and replay.** G1/G2 selections and frozen owner groups are projected into transaction-local SQLite relations, so later aliases, source heads and label changes cannot silently change earlier K. Input bundles retain canonical/effort version IDs, recorded samples, QC, interval reviews, workout layers, scale/calibration definitions, raw references and source receipt times. GET leaves the local database unchanged. Rebuilds use the captured bundle.
9. **Evidence limits.** Descriptive matches and a critical-speed fit have no calibrated personal predictive interval. Human Garmin inspection, independent prospective benchmarks and scientific validation remain separate work. Pain and worsening symptoms generate planning review signals. The fitness profile grants no mileage, diagnosis or prescription authority.
10. **Review and CI.** The issue branch is integrated with the merged availability and fueling changes. The PR records final independent review, regression evidence, the exact commit and the GitHub Actions test job. Merge requires the coordinator's independent verification of those results.
